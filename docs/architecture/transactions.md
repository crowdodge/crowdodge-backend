# トランザクション管理

## 更新対象

- トランザクション境界、外部API呼び出し位置、DB実装方式を変更した場合に更新する。

## 境界

- トランザクション境界は `application` のユースケース単位とする。
- 原則として、1ユースケースで1集約を変更する。
- `application` は `TransactionRunner` ポートを経由してトランザクションを開始する。
- `TransactionRunner` の実装は `infrastructure` に置く。

## 実行ルール

- 純粋な検証ロジックはトランザクション外で実行する。
- リポジトリは自前でトランザクションを開始しない。
- リポジトリはユースケースが開始した現在のトランザクションへ参加する。
- コンテキストをまたぐ変更は分散トランザクションにしない。
- コンテキスト間の整合性はドメインイベントによる結果整合性で扱う。
- Google Calendar、Gemini、FCM などの外部API呼び出しはトランザクション内に入れない。

## R2DBC

- 実行時トランザクションは Exposed R2DBC の `suspendTransaction` で実装する。
- R2DBC のトランザクションはコルーチンコンテキストに束縛される。
- トランザクション内で別ディスパッチャへ切り替えない。
