# Gemini

## 更新対象

- Geminiの利用目的、モデル構成、生成対象、失敗時の扱い、認証方式を変更した場合に更新する。

## 混雑予測

- Notification dispatch Cloud Run Jobから、予定に影響する混雑時間帯を生成する。
- 調査には`gemini-3.5-flash`とGoogle Search、結果の構造化には`gemini-3.1-flash-lite`を使用する。
- 予定の日時、目的地、往復経路、移動時間をもとに、実在するイベントと交通障害を調査する。
- 予測対象は、予定開始の「移動時間 + 2時間」前から、予定終了の「移動時間 + 2時間」後までとする。
- 生成する混雑時間帯は1予定につき最大3件とする。
- 調査結果と構造化結果が一致しない場合や、Google Searchの実行を確認できない場合は生成結果を採用しない。
- 経路上の検索の完全網羅は保証しない。

## 障害時の扱い

- 一時的な通信障害は、各通信につき最大2回まで試行する。
- 構造化処理だけを再試行する場合は、Google Searchによる調査をやり直さない。
- 再試行後も通信できない場合は一時的な生成失敗として扱う。
- 認証エラーや不正な応答は再試行せず、生成結果を採用しない。
- 処理のキャンセルは再試行しない。

## 認証

- Gemini APIの認証には`GEMINI_API_KEY`を使用する。
- APIキーはSecret ManagerからNotification dispatch Jobへ環境変数として注入する。
